# 工具管理 —— 完整功能介绍

`dsh-s-m-c-center` v0.0.3
设置页入口：**Web UI 插件 → 工具管理**

一个页面管三类工具，外加一个使用说明页：**技能（Skills）**、**MCP 服务器**、**本地 CLI 工具**、
**使用说明**。MCP 是真的连接、真的注册工具；技能走「储存器 + 联接」；
CLI 负责发现和体检；使用说明页讲清三类工具各自的工作方式，并负责把托管的数据双向归还。

---

## 1. 两个总开关

| 开关 | 作用 | 关掉会怎样 |
|---|---|---|
| **启用插件** | 主开关，控制路由、MCP 连接、公告 | 路由全部下线，所有 MCP 断开 |
| **向 Agent 公告** | 是否在每个 agent 的系统提示里声明本插件 | AI 完全不知道这个插件存在 |

两者写在 `~/.dsh/settings.yaml` 的 `dsh-s-m-c-center` 段，**切换即时生效，不用重启**。

常见误会：关「公告」**不会**断开 MCP。MCP 连接由「启用插件」控制。

## 2. 技能页签

按开关语义拆成**两个子页**（两个子页都列出全部技能，各自驱动一条轴；列表内排序：`.dsh` 来源在前，其它在后；长描述单行截断，详情看全文）：

| 子页 | 驱动的轴 | 规则 |
|---|---|---|
| **就地管理** | **1/2：是否注入上下文**（写入 / 移除 `SKILL.md` 前言标记，上游式） | 未收容的技能（文件本来就在扫描目录里）与**已发送快捷方式**的技能都可切换 1/2；快捷方式被移除（B）时**锁定为 2（禁用）** |
| **储存库** | **A/B：是否在 skills 文件夹发送快捷方式**（目录联接） | 发送（A）＝agent 经联接看到技能；移除（B）＝联接消失，就地管理页的开关随之锁定。未收容的技能不参与此轴（开关置灰，需先导入 / 收容） |

两条轴互不冲突，只是叠加：A∧1 注入、A∧2 不注入、B 锁定 2。未收容的外部技能只看 1/2。

### 2.1 扫描范围
  
四个根目录，按级别分组展示：

| 来源 | 路径 | 级别 |
|---|---|---|
| `project-dsh` | `<项目根>/.dsh/skills` | 项目级 |
| `project-agents` | `<项目根>/.agents/skills` | 项目级 |
| `user-dsh` | `~/.dsh/skills` | 用户级 |
| `user-agents` | `~/.agents/skills` | 用户级 |

项目根 = 从当前工作目录向上找最近的 `.git`。支持按名称搜索。

### 2.2 储存器机制（核心）

用户级技能的正本收进储存库的 `skills/` 目录（`~/.dsh/S-M-C/skills/`）：

```
~/.dsh/S-M-C/skills/
├── index.json          # 清单：slug / 原始路径 / 来源
└── <slug>/             # 每个技能一个 bundle，唯一正本
    └── SKILL.md
```

- **启用** = 在对应 skills 根目录建一条**目录联接** `~/.dsh/skills/<slug>` → 储存器
- **不启用** = 删掉这条联接
- **SKILL.md 从头到尾不被改写**

dsh 原生扫描器会跟随联接（`skill-filesystem` 的 `nodeEntryKind` 会对 symlink 条目再 `stat()`），
所以**联接在 = AI 看得见，联接不在 = AI 完全看不见**。语义和 CLI 的「公告 / 隐藏」一致。

**Agent 也会被引导到这里**：公告里明确告诉 AI —— 新建用户级技能时，把技能文件夹直接创建到
`~/.dsh/S-M-C/skills/<技能名>/`，不要写到 `~/.dsh/skills` 等储存库外的目录。这类"直接投放"的技能
即使还没有清单条目，也会以「未启用」状态出现在列表中（横幅计数同样计入）；用户启用时会自动补录清单，
从此纳入统一管理。

为什么要这样：以前启用/禁用靠改写前言里的 `disable-model-invocation`，而 dsh 对前言很严格 ——
拼错的键名或非布尔值会让**整个技能被丢弃并告警**。改成联接后彻底不碰用户文件。

### 2.3 迁移与撤销

- 插件加载时（dsh 启动）自动跑**一次**迁移，把用户级技能搬进储存库并回填联接
- 幂等：靠 `index.json` 里的 `migratedAt` 标记，第二次启动不会重复搬
- 单个技能搬迁失败只记录、不中断，技能**原样留在原位置仍可用**
- 页面顶部横幅说明储存器位置与数量；**「撤销迁移」按钮在「使用说明」页**
  （见第 5 章），技能页的横幅现在只报告状态
- **双向可逆**：撤销之后，「使用说明」页的同一位置会出现绿色「迁移」按钮，可再收回来

**项目级技能刻意不迁移**，仍用前言开关，UI 上标「就地管理」。
理由：搬到 `~/.dsh` 会让技能脱离它的仓库，克隆到别的机器上就没了，仓库移动还会留下悬挂联接。

### 2.4 其他操作

| 操作 | 行为 |
|---|---|
| 详情 | 展开显示 description / whenToUse / 正文全文 |
| 删除 | 两步确认（第一次点变成「再次点击确认删除」）。托管技能 = 删联接 + 删储存副本 + 删清单项；**不可恢复** |
| 扫描导入 | 填目录或点「选择文件夹」，勾选后导入；导入即入储存器并默认启用。**释放目标固定为 `~/.dsh/skills`**——无论从哪里导入，撤销迁移时技能都落到 dsh 的标准用户技能目录，而不是原选的任意路径 |
| 平铺 `.md` | 导入时自动 bundle 化成 `<slug>/SKILL.md`（联接只能指向目录） |

## 3. MCP 页签

管理 MCP 服务器，**连接是真的**：激活的服务器经 `@deepseek-ai/dsh-mcp-client` 真正连上，
把工具注册成 `mcp__<server>__<tool>`。

页签分**两个子页面**：

| 子页面 | 做什么 |
|---|---|
| **管理** | 列表：搜索、刷新，每行一个「激活 / 归档」开关，可删除。**暂不提供修改** —— 让一行只承载一个决定 |
| **新建** | 用表单或 JSON 定义一台新服务器，可先「测试连接」再保存；保存后自动回到管理页 |

| 能力 | 说明 |
|---|---|
| 传输 | `stdio` 与 `streamable-http` |
| 测试连接 | 一次性真实探测，先测再存 |
| 状态显示 | 连接中 / 运行中 / 失败（带错误原因）/ 已停止；归档行显示「未连接」 |
| 持久化 | 激活的存 `S-M-C/mcp.json`，归档的存 `S-M-C/mcp-archive.json` |

### 3.1 激活 / 归档

开关的两个状态是 **激活** 与 **归档**，和技能页签的「启用 / 不启用」、CLI 页签的
「公告 / 隐藏」是同一套语义：**关掉 = 彻底不在激活文档里**，而不是「在里面但打了个标记」。

- **归档**：整条定义从 `S-M-C/mcp.json` 移到 `S-M-C/mcp-archive.json`。
  连接立即断开、工具从 `mcp__<server>__<tool>` 列表消失、公告也不再提它。
- **激活**：移回 `S-M-C/mcp.json`，重新连接、重新注册工具。
- **定义完整保留**：归档不等于删除。行还在列表里（带「归档库」标记），随时可以点回来。
- **保存即为激活**：在「新建」页保存一条与归档条目同名的定义，它会直接回到激活文档。

首次启动会做一次**一次性迁移**：把旧的 `enabled: false` 定义自动搬进归档文件。
所以「没启用」现在只有一种写法，不会出现「文件里写着 enabled:false 但还在连」这种歧义。

> 为什么不做「只关掉某个服务器的某几个工具」：mcp-client 的 `Config` 没有过滤字段，
> dsh 的 `tools.restrict()` 又要求插件带 agent 上下文且工具已注册（我们是全局插件、MCP 工具是异步注册的），
> 两条路都走不通。整条定义归档是唯一诚实、也唯一能真正生效的粒度。

## 4. CLI 页签

| 能力 | 说明 |
|---|---|
| 自动发现 | 扫描技能内嵌的 CLI 包装脚本（`scripts/run-cli`、`cli-state`） |
| 来源标注 | 每行标出来源与位置：`技能 CLI · <路径>` 或 `系统 CLI · <路径>` |
| 系统 CLI 注册表 | `S-M-C/cli.json`，内置 `gh` / `git` / `tencent-news-cli`，可自行登记 |
| 公告 / 隐藏 | 唯一的开关，**默认隐藏**（默认值此前为「提供」） |
| 探测 | 是否安装 / 版本 / 需更新 / API-Key 状态 |
| 子命令 | 解析 `help` 输出列出子命令 |

**开关只管一件事**：是否把这个 CLI 写进给 AI 的公告。CLI 由系统安装、运行时也不归插件管，
所以插件既不能启动也不能停用它——「隐藏」只是让它不出现在公告里，CLI 本身照常可用。

**随 skills 安装的 CLI 建议保持隐藏**：它们在界面上标为「技能 CLI」，主要供自己的 skill 调用，
公告给 AI 只会撑大系统提示。注意这与插件自身的「向 AI 公告」开关不是一回事——那个公告的是插件能力。

保存到 `S-M-C/cli.json`；读取与保存走同一套归一化逻辑，保证每个 `enabled` 都是真布尔值。
技能型 CLI 没有自己的登记项，第一次拨动它的开关时会以同名条目写进注册表。

## 5. 使用说明

第四个页签既是**说明书**，也是**卸载前的总撤退口**：上半部分按工具分类讲清各自的工作方式，
下半部分是归还动作。

### 5.1 三类工具是怎么工作的

**技能（Skills）—— 储存库与目录联接**
用户级技能的正本统一放在储存库的 `skills/` 目录，各个 skills 目录里看到的是指向正本的目录联接。
界面只提供「启用 / 不启用」：启用 = 注入联接，AI 立刻能用；不启用 = 移除联接，AI 完全看不到。
两种情况都不改写 `SKILL.md`；项目级技能就地管理，仍按前言里的开关。

**MCP 服务器 —— 真实连接与归档**
激活的服务器经 `@deepseek-ai/dsh-mcp-client` 真正连接，工具注册为 `mcp__<server>__<tool>`。
归档把定义移到 `mcp-archive.json`：不连接、不公告，但完整保留，随时可以移回；
编辑一条已归档的服务器再保存，等同于激活它。

**本地 CLI 工具 —— 发现与公告**
自动发现 skill 内嵌的 CLI（`scripts/run-cli`）与登记的系统 CLI（`gh` / `git` 等），
探测是否安装、版本、是否需更新、API-Key 状态，并列出子命令。
开关只决定「是否把这个 CLI 写进给 AI 的公告」——CLI 由系统安装，插件无法启停它；
随 skills 安装的 CLI 建议保持隐藏，它们主要供所属 skill 自己调用，公告出去只会撑大系统提示。

（数据位置见第 7 章。）

### 5.2 卸载准备

与前三类工具并列的第四个页签，解决「不想用了怎么干净退出」。
核心动作是**归还**，拆成两个互不影响的选项：

| 选项 | 做什么 | 可逆吗 |
|---|---|---|
| **技能迁移** | 储存库里有技能时，显示红色「撤销迁移」：把每个技能按原状态还原回原路径、移除联接（**导入的技能例外**——它们的释放目标固定为 `~/.dsh/skills`，不回到导入时的任意目录）。储存库为空、而 skills 目录里还有技能时，同一位置变成**绿色「迁移」**，把技能重新收进储存库 | **双向可逆**（红 ↔ 绿随状态自动切换） |
| **MCP 注入** | 「MCP 全部注入」把归档的服务器一次性移回 `mcp.json` 并重新连接 | 不需要撤回——不需要的服务器随时能在「MCP 服务」页单独归档或删除 |

按钮状态由**真实数据推导**，不是手动切换：判定依据是「储存库里的技能数」+「skills 目录里未托管的技能数」。
所以点完「撤销迁移」、刷新后按钮会自己变成「迁移」，再点就收回来。

页面下半部分是**卸载前必须手动删除的文件**：插件卸载不会清理数据，得自己动手：

```
~/.dsh/S-M-C/            ← 删掉整个目录即可
├── skills/              （技能正本）
├── mcp.json             （激活的 MCP 服务器，含明文凭据）
├── mcp-archive.json     （归档的 MCP 服务器）
└── cli.json             （CLI 登记表）
```

`~/.dsh/settings.yaml` 里的 `dsh-s-m-c-center` 配置块也可一并删掉（不删只是留一段无用配置）。

> **为什么 MCP 不提供撤回？** MCP 的粒度本来就更细：不需要哪台服务器，随时能在「MCP 服务」页
> 单独归档或删除，不需要一个专门的「退回去」动作。

## 6. 向 Agent 公告

公告不是一段写死的话，而是**每次组装提示词时动态生成**，把机器上真实的东西列进去：
技能清单（含描述）、MCP 服务器（含连接状态与工具命名空间）、CLI 工具（含是否安装）。
带 5 秒缓存 + 变更即失效，所以管理页改完几乎立刻反映到系统提示。

三类工具对 AI 的可见性各不相同：

| 工具 | AI 怎么知道的 | 关掉公告会消失吗 |
|---|---|---|
| 技能 | dsh 原生 `<available_skills>` + `skill` 工具 | 不会 |
| MCP | 直接进工具列表，形如 `mcp__<server>__<tool>`；已归档的不在列表里，公告里注明「已归档」 | 不会（由「启用插件」控制） |
| CLI | **只有公告里这一处** | 会 —— 这是 CLI 唯一的曝光渠道 |

## 7. 数据落在哪里

### 6.1 统一外挂储存库 `~/.dsh/S-M-C`

插件自己产生的**全部**数据都在这一个目录里，名字就是里面装的东西：
**S**kills / **M**CP / **C**LI。

```
~/.dsh/S-M-C/
├── skills/             # 用户级技能的正本（唯一副本）
│   └── index.json      # 清单：slug / 原始路径 / 来源 / 启用状态
├── mcp.json            # 激活中的 MCP 服务器定义
├── mcp-archive.json    # 已归档的 MCP 定义（保留但不连接、不公告）
└── cli.json            # 本地 CLI 注册表
```

| 文件 | 内容 |
|---|---|
| `S-M-C/skills/index.json` | 技能储存清单 |
| `S-M-C/skills/<slug>/SKILL.md` | 技能正本，skills 目录里的只是指向它的联接 |
| `S-M-C/mcp.json` | 激活中的 MCP 服务器定义 |
| `S-M-C/mcp-archive.json` | 已归档的 MCP 定义 |
| `S-M-C/cli.json` | CLI 注册表 |

**有意留在库外的两项**：

| 路径 | 为什么不进来 |
|---|---|
| `~/.dsh/skills/`、`~/.agents/skills/` | dsh 自己的技能根，agent 只扫这里；我们做的是从这里**联接**进储存库 |
| `~/.dsh/settings.yaml` → `dsh-s-m-c-center` | dsh 的文档，我们只有其中一个命名空间段 |

### 6.2 移动它

整库跟随 `$DSH_HOME`（默认 `~/.dsh`）。想把它放到别的盘而不惊动 dsh，设一个变量即可：

```bash
DSH_STORE_ROOT=D:\my-tools\dsh-store
```

设了以后所有读写都走新位置，下次启动还会把旧位置残留的数据自动搬过去。

> 搬家时要小心的一点：skills 目录里的**联接记录的是绝对路径**。
> 手动剪切 `S-M-C` 会让这些联接全部指向不存在的路径，技能对 AI 瞬间消失。
> 用 `DSH_STORE_ROOT` 交给插件自己搬，它会在搬完后重建所有联接。

## 8. 安全边界

- 所有 `/api/dsh-s-m-c-center/*` 路由只接受 **loopback**（`127.0.0.1` / `::1`）请求，
  并校验 `Host`、`Origin` 同源、拒绝 `sec-fetch-site: cross-site`
- 这些接口会读写用户文件、拉起 MCP 服务器，所以**不要把 dsh web 暴露到局域网**

---

## 9. 已知限制

- 删除是物理删除，不可恢复
- MCP 配置里的密码 / env 是**明文**存储的，文件权限由用户自己保证
- CLI 不注册成工具，AI 只能通过终端/命令工具按名字调用
- 项目级技能不受储存器接管，仍是改写前言的老方式
- MCP 的开关粒度是**整条定义**（激活 / 归档），做不到「只关掉某个服务器的一部分工具」
- 公告有 5 秒缓存，管理页操作后最多延迟 5 秒才反映到系统提示
- 卸载插件后，已建的联接仍然指向 `S-M-C/skills`，技能对 dsh 依然可见（联接是透明的）。
  想彻底回到原样：先在「使用说明」页点「撤销迁移」，再删掉储存库目录
